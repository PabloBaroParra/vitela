# Code of Conduct

## Our standard

Vitela adopts the [Contributor Covenant, version 2.1][covenant] as its code of
conduct. Please read it — it is short, and it is the standard this project is
held to.

[covenant]: https://www.contributor-covenant.org/version/2/1/code_of_conduct/

In practice, it comes down to this: participate as someone who wants the project
and the people in it to get better. Disagree about code as much as you like —
technical disagreement is how the work improves — but disagree about the code.

Review comments are about the change, not the person who wrote it. If you are
on the receiving end of a hard review, that is the project taking your
contribution seriously. If you are giving one, explain the *why*: "this drops
the encryption flag on save" teaches something; "this is wrong" does not.

## Scope

This applies in every project space — issues, pull requests, discussions, commit
messages, code review — and whenever someone is representing Vitela in public.

## Reporting

Report unacceptable behaviour privately to the maintainers by opening a
[private security advisory][report], which is the only private channel this
repository has. Mark it clearly as a conduct report rather than a vulnerability.

[report]: https://github.com/PabloBaroParra/vitela/security/advisories/new

Every report is reviewed and investigated, and the reporter's privacy and safety
are respected. You will not be penalised for reporting in good faith.

## Enforcement

Maintainers are responsible for clarifying and enforcing this standard, and may
edit or remove comments, commits, code, issues and pull requests that do not
follow it — with a reason given where it is appropriate to give one.

Consequences follow the Contributor Covenant's enforcement ladder: a private
correction, then a warning, then a temporary ban, then a permanent ban.
Maintainers who do not enforce the standard in good faith can expect
repercussions themselves.
